🟢 Level 1 — Beginner L1

1. Creating a Display
The Display class is the foundation of every Limn Engine game — it creates the HTML5 canvas, attaches it to the page, listens for keyboard and mouse input, and starts the game loop that drives everything.

What we're going to do: Create the smallest possible Limn Engine game — just a canvas and an empty update loop. This is the starting point for every game you will ever build.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>My First Limn Game</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    // Create the engine
    const display = new Display();

    // Start it — creates the canvas and begins the game loop
    display.start(800, 600);

    // Optional: set a background colour
    display.backgroundColor("#0d0d2a");

    // The update() function runs every frame automatically
    function update(dt) {
      // Your game logic will go here
    }
  </script>
</body>
</html>

What we just did:

  • Loaded the Limn Engine library with <script src="epic.js">
  • Created a Display instance — this is the engine itself
  • Called display.start(800, 600) — this creates the canvas on the page and begins the game loop
  • Set the background colour with display.backgroundColor()
  • Defined an empty update(dt) function — this will be called every frame automatically, and dt is the delta time
⚠️ Your Display instance must be named display — the engine uses this variable name internally across Component, Camera, TileMap, and many other classes.
Method / PropertyParametersPurpose
new Display()NoneCreate the engine — canvas, input, loop, camera are all set up
display.start(w, h, node)width, height, node=document.bodyCreate the canvas at that size and start the game loop
display.backgroundColor(color)CSS color stringSet the canvas background colour
display.stop()NonePause the game loop
display.fullScreen()NoneEnter fullscreen mode

2. Adding & Moving Components
A Component is any visible object in your game — the player, an enemy, a coin, a wall — and it needs to be registered with display.add() before Limn Engine will draw or update it each frame.

What we're going to do: Create a player component, add it to the display, and make it move continuously across the screen using speedX and speedY.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Components</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    // Component(width, height, color, x, y, type)
    const player = new Component(50, 50, "blue", 100, 200, "rect");
    display.add(player);

    // Make it move continuously — engine applies this every frame
    player.speedX = 3;  // 3 pixels per frame to the right
    player.speedY = 2;  // 2 pixels per frame down

    function update(dt) {
      // Stop the player when it reaches the right edge
      if (player.x > 750) {
        player.stopMove();
      }
    }
  </script>
</body>
</html>

What we just did:

  • Created a Component with width 50, height 50, colour "blue", at position (100, 200), drawn as a rectangle
  • Added it to the display with display.add(player) — without this the component would exist but never appear
  • Set speedX and speedY so the engine automatically moves the component each frame
  • Added a stop condition in update() — when the player reaches x = 750, it calls stopMove() to halt all movement
💡 The canvas origin (0,0) is the top-left corner. X increases going right. Y increases going down.
PropertyTypePurpose
x / ynumberWorld position — the top-left corner of the Component
width / heightnumberSize in pixels
speedX / speedYnumberVelocity added to x/y every frame automatically
colorstringFill colour (rect mode) or image path (image mode)
angleradiansRotation angle — engine applies it on draw

The three Component types:

  1. "rect" — draws a filled colour rectangle (default if omitted)
  2. "image" — draws a loaded image; pass the file path as the color argument
  3. "text" — draws text; use Tctxt for more control

3. Keyboard Input & deltaTime
Limn Engine fills the display.keys[] array with true while a key is held and false when it is released, letting you read any key by its numeric keyCode inside update() — and multiplying by dt (deltaTime) makes your movement the same speed on every machine.

What we're going to do: Make a player move with both the arrow keys and WASD, using dt so the movement is frame-rate independent. We'll also add a Space-bar action that fires only once per press.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Keyboard Input</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.perform(); // enables true deltaTime
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    const player = new Component(50, 50, "cyan", 375, 275, "rect");
    display.add(player);

    function update(dt) {
      // Reset every frame so the player stops when no key is held
      player.speedX = 0;
      player.speedY = 0;

      // Arrow keys
      if (display.keys[37]) player.speedX = -250 * dt;
      if (display.keys[39]) player.speedX =  250 * dt;
      if (display.keys[38]) player.speedY = -250 * dt;
      if (display.keys[40]) player.speedY =  250 * dt;

      // WASD
      if (display.keys[65]) player.speedX = -250 * dt;
      if (display.keys[68]) player.speedX =  250 * dt;
      if (display.keys[87]) player.speedY = -250 * dt;
      if (display.keys[83]) player.speedY =  250 * dt;

      // Single-press action — Space fires only once per key press
      if (display.keys[32]) {
        display.keys[32] = false; // reset the key
        player.setColor("yellow");
      }
    }
  </script>
</body>
</html>

What we just did:

  • Called display.perform() before display.start() so dt is accurate
  • In update(dt), reset player.speedX and player.speedY to 0 at the start — this makes the player stop when no key is held
  • Checked each key with display.keys[keyCode] and set the speed accordingly
  • Multiplied each speed by dt so movement is in pixels per second, not pixels per frame
  • For the Space bar, set display.keys[32] = false after handling it, so it only fires once per press

← Left Arrow37A65
↑ Up Arrow38W87
→ Right Arrow39D68
↓ Down Arrow40S83
Space32Enter13
Escape27Shift16

4. Boundaries with move.bound()
move.bound() prevents a Component from walking off any edge of the canvas by clamping its position to the canvas boundaries every frame — one line of code that replaces four manual if-checks.

What we're going to do: Add boundary checking to a moving player so it can never leave the visible canvas.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Boundaries</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    const player = new Component(50, 50, "cyan", 375, 275, "rect");
    display.add(player);

    function update(dt) {
      player.speedX = 0;
      player.speedY = 0;

      if (display.keys[39]) player.speedX =  250 * dt;
      if (display.keys[37]) player.speedX = -250 * dt;
      if (display.keys[38]) player.speedY = -250 * dt;
      if (display.keys[40]) player.speedY =  250 * dt;

      // Clamp to all four canvas edges — one line
      move.bound(player);
    }
  </script>
</body>
</html>

What we just did: We called move.bound(player) after every movement update. This reads the canvas width and height from display.canvas and clamps the player's x and y so the component can never go past any of the four edges. It also accounts for the component's own width and height so the whole rectangle stays visible.

If you need custom boundaries instead of the full canvas, use move.boundTo():

Full runnable code — custom boundaries 
<!DOCTYPE html>
<html>
<head>
  <title>Custom Boundaries</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    const player = new Component(50, 50, "cyan", 375, 275, "rect");
    display.add(player);

    function update(dt) {
      player.speedX = 0;
      player.speedY = 0;

      if (display.keys[39]) player.speedX =  250 * dt;
      if (display.keys[37]) player.speedX = -250 * dt;
      if (display.keys[38]) player.speedY = -250 * dt;
      if (display.keys[40]) player.speedY =  250 * dt;

      // Clamp to a custom region: left=100, right=700, top=100, bottom=500
      move.boundTo(player, 100, 700, 100, 500);
    }
  </script>
</body>
</html>

What we just did: We called move.boundTo(player, left, right, top, bottom) with explicit pixel values. Passing false for any side leaves that side open — for example, move.boundTo(player, 0, 800, false, false) only clamps horizontally.

MethodParametersPurpose
move.bound(id)ComponentClamp to all four canvas edges — accounts for Component size
move.boundTo(id,l,r,t,b)Component, left, right, top, bottom (or false)Clamp to custom pixel boundaries per side

5. Rectangle Collision with crashWith()
crashWith(other) is Limn Engine's standard collision detection method — it checks whether the bounding rectangles of two Components overlap and returns true if they do, giving you the foundation for hit detection, pickups, and obstacle collision in a single call.

What we're going to do: Create a player, a coin, and a wall. Collect the coin when you touch it, and stop when you hit the wall.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Collision</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    const player = new Component(40, 40, "blue", 100, 300, "rect");
    const coin   = new Component(20, 20, "gold", 400, 200, "rect");
    const wall   = new Component(200, 20, "gray", 300, 350, "rect");

    display.add(player);
    display.add(coin);
    display.add(wall);

    let score = 0;

    function update(dt) {
      player.speedX = 0;
      player.speedY = 0;

      if (display.keys[39]) player.speedX =  250 * dt;
      if (display.keys[37]) player.speedX = -250 * dt;
      if (display.keys[38]) player.speedY = -250 * dt;
      if (display.keys[40]) player.speedY =  250 * dt;

      // Collect coin on touch
      if (player.crashWith(coin)) {
        score++;
        coin.x = Math.random() * 760;
        coin.y = Math.random() * 560;
      }

      // Stop at wall
      if (player.crashWith(wall)) {
        player.speedX = 0;
        player.speedY = 0;
      }

      move.bound(player);
    }
  </script>
</body>
</html>

What we just did: We used crashWith() to detect overlap between the player and both the coin and the wall. When the player touches the coin, we increase the score and teleport the coin to a new random position. When the player touches the wall, we stop its movement.

MethodReturnsHow it works
a.crashWith(b)booleanAABB overlap check — rotation-aware

6. Text with Tctxt
Tctxt is Limn Engine's rich text Component — it extends the base Component class with font size, font family, text alignment, an optional background fill with padding, and a baseline setting, making it the correct tool for any score display, dialogue box, or on-screen UI label.

What we're going to do: Add a score display that is locked to the top-left corner of the screen and updates every frame.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Text with Tctxt</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    const player = new Component(40, 40, "cyan", 375, 275, "rect");
    display.add(player);

    // Tctxt(size, font, color, x, y, align, stroke, baseline, background, padX, padY)
    const scoreText = new Tctxt(
      "22px",             // font size
      "Arial",            // font family
      "white",            // text colour
      20, 36,             // x, y position on screen
      "left",             // alignment
      false,              // stroke = false → filled text
      "alphabetic",       // text baseline
      "rgba(0,0,0,0.6)",  // background fill colour
      14, 6               // paddingX, paddingY
    );
    scoreText.setText("Score: 0");
    display.add(scoreText);

    let score = 0;

    function update(dt) {
      // Move player with arrow keys
      player.speedX = 0;
      player.speedY = 0;
      if (display.keys[39]) player.speedX =  250 * dt;
      if (display.keys[37]) player.speedX = -250 * dt;
      if (display.keys[38]) player.speedY = -250 * dt;
      if (display.keys[40]) player.speedY =  250 * dt;

      // Increase the score over time as a demo
      score += 60 * dt;
      scoreText.setText("Score: " + Math.floor(score));

      // Lock the score box to the screen
      scoreText.fixed();
    }
  </script>
</body>
</html>

What we just did:

  • Created a Tctxt component with all eleven constructor parameters, giving us full control over how the text is drawn
  • Set the background to "rgba(0,0,0,0.6)" so the text is readable against any game background
  • Added padding of 14 pixels horizontally and 6 pixels vertically around the text inside the background box
  • Called scoreText.setText() in update() to refresh the displayed string
  • Called scoreText.fixed() every frame to lock the text to the top-left of the screen — without this it would scroll away with the camera
💡 fixed() works by adding the current camera offset to the Component's stored aX / aY anchor position every frame, keeping it at the same screen coordinates no matter where the camera is. You must call it every frame — not just once.

size"22px"Font size as a CSS string
font"Arial"Font family name
align"left""left", "center", or "right"
strokefalsefalse = filled text, true = outlined text only
background"rgba(0,0,0,0.6)"Background fill — null disables it

7. Images with setImage()
Any Component can display an image instead of a coloured rectangle — either by passing "image" as the type at construction, or by calling setImage(src) at any point to switch to image mode, with automatic fallback to a red rectangle if the file fails to load.

What we're going to do: Create a player using a plain rectangle, then swap it to an image at runtime. We'll also show how to switch back to a colour if needed.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Images</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    // Start as a coloured rectangle
    const player = new Component(64, 64, "cyan", 100, 100, "rect");
    display.add(player);

    // Switch to an image at runtime
    player.setImage("img/hero.png");

    // Create a second component that starts as an image
    const enemy = new Component(40, 40, "img/enemy.png", 400, 300, "image");
    display.add(enemy);

    function update(dt) {
      player.speedX = 0;
      player.speedY = 0;

      if (display.keys[39]) player.speedX =  250 * dt;
      if (display.keys[37]) player.speedX = -250 * dt;
      if (display.keys[38]) player.speedY = -250 * dt;
      if (display.keys[40]) player.speedY =  250 * dt;

      move.bound(player);
      move.bound(enemy);

      // Press S to switch the enemy back to a purple rectangle
      if (display.keys[83]) {
        display.keys[83] = false;
        enemy.setColor("purple");
      }
    }
  </script>
</body>
</html>

What we just did:

  • Created the player as a "rect" component, added it to the display, then called player.setImage("img/hero.png") to swap it to image mode at runtime
  • Created the enemy directly in image mode by passing "img/enemy.png" as the colour argument and "image" as the type
  • Added an S-key action that calls enemy.setColor("purple") — this clears the image and switches back to rectangle mode
  • If any image fails to load (wrong path, missing file), the engine automatically falls back to a red rectangle so you can see the problem
MethodParametersBehaviour
setImage(src)file path stringLoad an image — falls back to red rect on error
setColor(color)CSS color stringSwitch back to filled rect, clears the image

8. Mouse Input & clicked()
Limn Engine stores the mouse position in display.x and display.y while any mouse button or finger is pressed — setting them to false on release — and clicked() lets you check whether the press landed specifically on a given Component.

What we're going to do: Create a button that changes colour when the mouse is pressed on it, and resets when the mouse is released. Works on touchscreens too.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Mouse Input</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    const btn = new Component(160, 50, "#7fffb2", 320, 270, "rect");
    display.add(btn);

    let clicks = 0;

    function update(dt) {
      // Check if mouse pressed specifically on the button
      if (display.x && btn.clicked()) {
        btn.setColor("lime");
        clicks++;
        console.log("Button clicked! Total clicks:", clicks);
      } else {
        btn.setColor("#7fffb2");
      }
    }
  </script>
</body>
</html>

What we just did:

  • Checked display.x to confirm the mouse is currently pressed (it is false when released)
  • Called btn.clicked() to test whether the press coordinates fall inside the button's rectangle
  • Changed the button colour to lime and logged the click when both conditions are true
  • Reset the colour back to the default when the condition is false
💡 Works on touchscreen too — touchstart sets display.x and display.y to the finger position, and touchend resets them to false.

9. Sound with the Sound Class
The Sound class wraps the browser's Audio API to give you simple load-and-play audio with volume control, looping, pause, and automatic clone-on-overlap so the same sound file can play multiple times simultaneously without cutting itself off.

What we're going to do: Load three sounds — a jump effect, a hit effect, and looping background music — then play them in response to game events.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Sound</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    // Create sounds BEFORE display.start() so they preload
    const jumpSfx = new Sound("audio/jump.wav");
    const hitSfx  = new Sound("audio/hit.wav", { volume: 0.8 });
    const bgMusic = new Sound("audio/music.mp3", { loop: true, volume: 0.5 });

    // Start background music
    bgMusic.play();

    const player = new Component(40, 40, "cyan", 375, 275, "rect");
    display.add(player);

    function update(dt) {
      player.speedX = 0;
      player.speedY = 0;

      if (display.keys[39]) player.speedX =  250 * dt;
      if (display.keys[37]) player.speedX = -250 * dt;
      if (display.keys[38]) player.speedY = -250 * dt;
      if (display.keys[40]) player.speedY =  250 * dt;

      // Space bar → play jump sound (clones so rapid presses all play)
      if (display.keys[32]) {
        display.keys[32] = false;
        jumpSfx.play();
      }
    }
  </script>
</body>
</html>

What we just did:

  • Created three Sound objects at the top of the script — this starts preloading immediately, before the game begins
  • Passed an options object { volume: 0.8 } to set the hit sound quieter than default
  • Passed { loop: true, volume: 0.5 } to the background music so it repeats forever at half volume
  • Called bgMusic.play() to start the music
  • Played jumpSfx on every Space press — if the sound is still playing, the engine creates a temporary clone so nothing is cut off

10. Game States with display.scene
display.scene is Limn Engine's scene management system — every Component is registered to a scene number, and only Components whose scene number matches display.scene are drawn and updated each frame, letting you switch between a main menu, gameplay, and game-over screen with a single assignment.

What we're going to do: Build a mini game with a main menu, a playable scene, and a game-over screen. Click a button on the menu to start; reach a certain score to trigger game over.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Scenes</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    // ── Scene 0 — main menu ──
    const playBtn = new Component(160, 50, "#7fffb2", 320, 270, "rect");
    display.add(playBtn, 0);

    const title = new Tctxt("40px","Arial","white",400,180,"center");
    title.setText("LIMN GAME");
    display.add(title, 0);

    // ── Scene 1 — gameplay ──
    const player = new Component(40, 40, "cyan", 100, 100, "rect");
    display.add(player, 1);

    let playerDead = false;
    let timer = 0;

    // ── Scene 2 — game over ──
    const gameOverText = new Tctxt("36px","Arial","red",400,280,"center");
    gameOverText.setText("GAME OVER");
    display.add(gameOverText, 2);

    // Start on the menu
    display.scene = 0;

    function update(dt) {
      if (display.scene === 0) {
        // Menu — wait for a click on the play button
        if (display.x && playBtn.clicked()) {
          display.scene = 1;
          timer = 0;
          player.x = 100;
          player.y = 100;
          playerDead = false;
        }
      }

      if (display.scene === 1) {
        // Gameplay — move player and count down
        player.speedX = 0;
        player.speedY = 0;
        if (display.keys[39]) player.speedX =  250 * dt;
        if (display.keys[37]) player.speedX = -250 * dt;
        if (display.keys[38]) player.speedY = -250 * dt;
        if (display.keys[40]) player.speedY =  250 * dt;
        move.bound(player);

        timer += dt;
        if (timer > 5) { // end after 5 seconds as a demo
          playerDead = true;
          display.scene = 2;
        }
      }

      if (display.scene === 2) {
        // Game over — click to return to the menu
        if (display.x) {
          display.scene = 0;
        }
      }
    }
  </script>
</body>
</html>

What we just did:

  • Created three scenes by passing a second argument to display.add() — the scene number
  • Assigned the play button and title to scene 0, the player to scene 1, and the game-over text to scene 2
  • Set display.scene = 0 to start on the menu
  • In update() we used if (display.scene === 0), === 1, and === 2 to run different logic depending on the active scene
  • Switched scenes by simply assigning a new number — all objects for that scene became active instantly, and all others became inactive
💡 Components default to scene 0 if you call display.add(obj) without a second argument — so beginner games that only have one screen never need to think about scene numbers.

11. Coin Collector — Complete Tutorial
This tutorial builds a complete game from scratch using only Level 1 concepts — movement, collision, a score counter, boundaries, and a Tctxt HUD — to show how the pieces fit together into a working, playable game.

What we're going to do: Build a complete coin-collecting game. The player moves with WASD, collects gold coins, and the score updates in a fixed HUD. Coins respawn at new random positions so the game never ends.

Full runnable code 
<!DOCTYPE html>
<html>
<head>
  <title>Coin Collector</title>
  <script src="epic.js"></script>
</head>
<body>
  <script>
    const display = new Display();
    display.perform();
    display.start(800, 600);
    display.backgroundColor("#0d0d2a");

    // Player
    const player = new Component(40, 40, "cyan", 380, 280, "rect");
    display.add(player);

    // Five coins at random positions
    const coins = [];
    for (let i = 0; i < 5; i++) {
      const c = new Component(
        20, 20, "gold",
        50 + Math.random() * 700,
        50 + Math.random() * 500,
        "rect"
      );
      display.add(c);
      coins.push(c);
    }

    // Score HUD — fixed to screen
    const scoreText = new Tctxt(
      "22px","Arial","white", 16, 36,
      "left", false, "alphabetic",
      "rgba(0,0,0,0.55)", 12, 6
    );
    scoreText.setText("Score: 0");
    display.add(scoreText);

    let score = 0;

    function update(dt) {
      // WASD movement with deltaTime
      player.speedX = 0;
      player.speedY = 0;
      if (display.keys[87]) player.speedY = -250 * dt;
      if (display.keys[83]) player.speedY =  250 * dt;
      if (display.keys[65]) player.speedX = -250 * dt;
      if (display.keys[68]) player.speedX =  250 * dt;

      // Stay inside canvas
      move.bound(player);

      // Collect coins
      for (let i = 0; i < coins.length; i++) {
        if (player.crashWith(coins[i])) {
          // Respawn at a new random position
          coins[i].x = 50 + Math.random() * 700;
          coins[i].y = 50 + Math.random() * 500;
          score++;
          scoreText.setText("Score: " + score);
        }
      }

      // Keep HUD fixed to screen
      scoreText.fixed();
    }
  </script>
</body>
</html>

What we just did:

  • Created a player component in the centre of the canvas
  • Looped five times to create five coins, each at a random position, and stored them in the coins array so we can check them all for collision
  • Created a Tctxt HUD to display the score, with a semi-transparent black background so it's readable anywhere
  • In update(dt), we move the player with WASD, multiply by dt for frame-rate independence, and call move.bound() to keep the player on screen
  • Looped through every coin, checking player.crashWith(coin) — on collision we teleport the coin to a new random position, increment the score, and update the HUD text
  • Called scoreText.fixed() every frame to lock the score to the top-left of the screen

✅ WASD to move. Walk into gold squares to collect them — each coin respawns at a new position. The score counter stays fixed to the top-left corner even if a camera is added later.
